# 数据记录 vs 运行时真相 —— PDF 底部"1 / …"

## 症状
PDF 底部栏显示 `当前页 1 / …`（总页数无法解析，显示 `…`）。

## 根因
- `handleOpenPdfFile` 创建 PdfFile 时 **`pageCount: 0` 硬编码**（从未设置）
- 底部栏从 `pdfs` 记录的 `pageCount` 读总页数 → 0 → 显示 `…`
- 但**真实页数**在 `PdfView` 加载的 pdf.js doc（`loaded.pageCount`）里始终可用——记录与运行时真相脱节

## 修复
- `PdfView` 加载 doc 后经 `onPageCountChange` 回调上报真实页数
- 底部栏改读**激活视图上报的值**（pdf.js doc 是唯一真相源），不再读 `pdfs` 记录的 0

## 通用教训
- **持久化记录的派生字段（pageCount）与运行时实态（已加载的 doc）会脱节**——显示层用运行时真相
- 硬编码 0 / 占位值是"待填"信号，但不会自动被填——要么加载时写回，要么显示层绕过
- 底部栏 `X / …` 的 `…` 兜底是"数据未知"的诚实表达，但也掩盖了根因（记录从未写对）
